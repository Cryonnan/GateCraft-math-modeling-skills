# 数学建模竞赛全流程总控（编排入口）

本 skill 是数模任务的**总控**：它不亲自建模，而是把任务拆成阶段、指定每个阶段调用哪个 skill、用报告文件做阶段交接、最后验收。

## 两种模式

- **流水线模式**（默认，一条命令跑到底）：按下方「五阶段流水线」执行。
- **时间线模式**（人工组队、Day1-3 真实赛制）：按下方「Day1-3 时间线」执行，阶段报告同样要写。

> 提示词资产包：`../../assets/prompt-pack.md`（14 条实战验证的提示词，按比赛阶段复制使用；本 skill 的检查项即这些提示词的制度化）。

## 必须产出（两种模式都要）

```text
plan.md                              # 本 skill 制定：题目拆解、阶段顺序、每阶段调用谁、产出什么
todo.md                              # 阶段 checklist（完成一项勾一项）
reports/ANALYSIS_MODELING_REPORT.md   # 阶段1产物：赛题分析+建模方案
reports/RESULTS_REPORT.md             # 阶段2产物：代码结果+图表清单+约束校验
reports/SENSITIVITY_REPORT.md         # 阶段3产物：灵敏度分析（sensitivity-analysis skill 产出）
reports/DIAGNOSIS_REPORT.md           # 阶段4产物：统计诊断（statistical-diagnosis skill 产出）
reports/VERIFY_REPORT.md              # 阶段5产物：提交前验收
```

**数值纪律（贯穿全程）**：论文里的每个数字必须能追溯到 reports/ 里的报告或代码输出；任何 skill 不得编造数值。改脚本重跑后必须做「论文数字↔csv/报告」一致性核对，零漂移才算通过（华数杯 2026 实测铁律）。

**阶段门（gate，华数杯实战铁律）**：每阶段/每问完成后必须写报告并自检——不达标（预测 R² 低于自定门槛、求解不可行、检验不过、指标异常）必须继续优化；一个子问题允许迭代 2-3 轮，每轮把「改动→效果→指标」记入报告；上一阶段报告未通过判定标准，不得进入下一阶段。

**交付命名规范（跨会话可交接）**：`数据预处理-数据预处理.py`、`问题一-problem1.py`…`问题四-problem4.py`（各带附件说明）、每题一个 `报告N.md`（记录子问题分解、模型依据、迭代记录、最终指标）、`paper/main.tex`→PDF。

## 五阶段流水线

| 阶段 | 做什么 | 调用 | 产物 |
|------|--------|------|------|
| 0 读题 | OCR 题面 PDF/附件图片落盘；外部解题指南/参考方案逐条核验（对照题目+附件数据实测）；文献 DOI/卷期核验（Crossref/OpenAlex，检索不到即标"无法核实"，禁编造） | `vision-ocr` + 直接执行（核验清单见 prompt-pack A1/A2） | 题面文本文件（不入对话，按需取段）+ 外部资料核验清单 |
| 0.5 数据结构探索 | 按 EDA 五问探数据，每条发现注明"→决定了哪个模型的哪个设计"与判定阈值 | 直接执行（见下） | 写入 ANALYSIS_MODELING_REPORT.md「数据结构发现」节 |
| 1 分析建模 | 子问题拆解、假设预检、符号、目标/约束、求解策略、代码任务清单 | 直接执行（见下） | ANALYSIS_MODELING_REPORT.md |
| 2 代码结果 | 按报告写可复现代码、跑数、画数据图、约束校验 | 直接执行 + `statistical-diagnosis`（模型诊断部分） | code/ + figures/ + RESULTS_REPORT.md |
| 3 灵敏度 | 按题型做灵敏度/稳健性分析 | `sensitivity-analysis` | SENSITIVITY_REPORT.md |
| 4 论文 | 内容走写作规范，排版走 LaTeX 模板；需要 Word 版再转 | `math-modeling-paper` → `math-paper-template` →（可选）`tex-pdf-image-to-word` | paper/*.tex → PDF |
| 5 验收 | 结构/格式/数值/复现/编译逐项验收 | `statistical-diagnosis` 复核 + 下方「提交前检查清单」 | VERIFY_REPORT.md |

### 阶段 0.5 要点（数据结构探索：EDA 五问）

大数据量题（尤其优化类）**强制**：建模依据必须来自数据而非直觉。每条发现写入报告的「数据结构发现」节，格式为"发现 + 判定阈值/口径 + → 决定了哪个模型的哪个设计"；无下游对应的发现标注"仅描述性"，不得写入建模依据。

1. **序列结构**：自相关/Ljung-Box 检验 → 是否白噪声（判定阈值：|ACF|<0.1 且 Q 检验 p>0.05）→ 决定预测模型是否走分解结构；
2. **规模瓶颈**：峰值需求与可用容量逐时对比 → 超容位置与幅度 → 决定优化对象与时移/迁移必要性；
3. **口径审计**：字段结构、统一计算口径、边界条款逐条核对（判定：每条建模假设能找到题面出处；题面"说明"条款必须全部落位）；
4. **信息极限**：可预测成分占比、水平跳变检验 → 哪些序列值得建模，哪些如实声明"已近信息极限"（判定：按步 R² 与在途成分占比）；
5. **相关结构**：目标间相关性的多口径检验（截面/时序/混合，分口径报相关系数）→ 多目标是否真冲突、前沿是否可能坍缩。

「发现→模型设计」映射表与求解降级链见 `../../assets/optimization-playbook.md`。

### 阶段 1 要点（分析建模，参考 MathModelAgent 2analysis 机制）

1. **子问题只认题面编号的顶层问题**（问题一/二/三…），别把背景、数据说明、小问当独立子问题。
2. **假设敏感性预检**：对影响结果的歧义至少给两种解释，用简单验算/递进性判断选一个；若后续问题的新增条件在当前解释下没有边际效果，回头改解释。
3. 每问必须写清：目标、符号变量、模型假设、目标函数、约束、求解方法、输入输出、结果校验方法；公式细到代码能直接实现。
4. 报告末尾写「代码实现任务清单」：| 任务 | 输入 | 输出 | 方法 | 校验 |。
5. 每问写「连贯链」三行：**继承**（复用上一问的符号/公式/参数，与符号表一致）／**新增**（本问新增决策变量/约束/目标项＝与前问构件集做差的结果）／**变因**（方法改变的原因，指向题目新增条件或数据发现）。——这是论文 R1 定位陈述的事实来源（见 `guozhan-paper` 3.5）。
6. 每个主要模型的选型必须引用「数据结构发现」或候选模型对比，禁用无依据的"本文采用 X 模型"（判定标准见 `guozhan-paper` 3.5 R2）。
7. 每问产出「流程图草稿」：四阶段节点文字（数据／模型／约束检验／求解与敏感性）+ 总体路线图的传递物标注；**草稿按 spec JSON 格式落盘**（格式、生成器与 OCR 复核链路见 `../../assets/figure-playbook.md` 第 4 节与 `../../assets/flowchart_gen.py`）——阶段 2 用生成器产出 .drawio/.mmd/.png，阶段 5 用 vision-ocr 读回 PNG 逐项复核。
8. 每个主要模型必须列出「可解释性更强的备选模型」并写明取舍理由（实战要求：基础模型/组合模型优先、解释性优先于黑箱；取舍理由写入报告）。

### 阶段 2 要点（代码与结果）

1. 先保证**可行解**再优化目标；输出方案逐条回代检查约束（scipy 不等式是 `fun(x)>=0`，最大化要取负——常见翻车点）。
2. 随机算法固定种子、多跑报告均值±std；预测类必须防数据泄露（时序不 shuffle、scaler 只在训练集 fit）。
3. 每个关键数值写进 RESULTS_REPORT.md；图按「显示宽→figsize」规则渲染（见 `../../assets/huashubei-writing-guide.md` 2.1，禁 bbox_inches='tight'）。
4. 验证三件套（大数据量优化类强制）：①可行性回代（判定：零违例）；②小规模精确对照（块级/子问题 MILP 重解报间隙；启发式不得宣称全局最优）；③独立复算（按附件口径重算，判定：数值链零漂移）。优化类附加收敛性声明（迭代序列递减）与最优性声明（LP 对偶/间隙），无法证明则如实声明。求解降级链与决策表见 `../../assets/optimization-playbook.md`。
5. 性能门槛：求解器单次运行超过约 10 分钟必须评估换算法（如滚动 MILP→贪心构造+局部搜索），并保留小规模精确求解做质量对照（华数杯实测：几小时→93 秒、块级 MILP 间隙 0%；换算法触发与质量验证见 playbook 降级链）。

### 阶段 3-4 要点

- 灵敏度/诊断**必须做**，独立成节；调用前先把题面与 RESULTS_REPORT.md 交给对应 skill，让它们按题型自适应（不是套 θ 模板）。
- 论文：`math-modeling-paper` 管内容（结构/摘要/表述/严谨性），`math-paper-template` 管排版（LaTeX/格式/编译）；两者都对齐 `../../assets/official-paper-format.md`。
- 评委/组织方要求 Word 版时：走 `tex-pdf-image-to-word` 路线 A（tex→docx），并过它的 11 条交付检查清单。

### 阶段 5 要点（验收）

硬错误：占位符残留、图缺失、数值与报告冲突、编译失败、页眉没去掉、图内字号 <9pt、表注漏特殊值——有任一即 FAIL。用 `guozhan-paper` 的国奖检查表对一遍档次。

脚本化检查（每条有判定标准，全部通过才可提交；脚本思路见 `../../assets/optimization-playbook.md` 第 6 条）：
1. 摘要数字映射：抽取摘要段全部数字，逐一映射到正文表格；未映射即 FAIL（反例：大湾区杯摘要与正文方案完全无关）。
2. 图表编号对账 v2：正文引用集合 ⊆ caption 集合、无缺号/重号、图/表前缀分离（禁"图表N"混用）、无章节号残留（grep `\d\.\d` 式残留，如"3.1.2""2.3.4"）。
3. AI 痕迹扫描：grep GPT/DeepSeek/Claude/Qwen/Kimi 等工具名，正文命中即 FAIL（附录 AI 使用记录除外；模型名必须真实发布）。
4. 表内自洽抽样：λ↔半衰期、权重和=1、CAGR↔份额 等列间数学关系逐列验算。
5. 正文页数硬检查：按赛题要求数页码（国赛 ≤20、华数杯 ≤30）。
6. 外部诊断复算：对任何审查意见/第三方诊断报告逐条复算，只采信实测成立的部分（"分析他说的是不是对的"模式；华数杯实测：审查报告 80% 正确但 3 处机制错误，全部被复算拦截）。
7. 文献一致性：关键结果与文献量级/方向对照（降幅远超文献上限时必须用"绝对量+机制"双口径解释）；参考文献顺序与正文引用顺序一致、每条可核实、不编造卷期页码（prompt-pack A2/D3）。

# Day1-3 时间线模式（人工赛制节奏）

## Day 1：拆解 + 数据 + 建模
- 08:00-10:00 选题：读题（OCR 落盘）→ 评估数据可得性/知识储备/创新点 → 定题
- 10:00-12:00 拆解分工：子问题类型（评价/预测/优化/分类）→ 依赖链 Q1→Q4 → 分工
- 12:00-14:00 数据结构探索：EDA 五问落盘（每条发现标注"→ 模型设计"与判定阈值；大数据量优化题强制，不得跳过）
- 14:00-22:00 Q1/Q2 建模求解：目标函数+约束显式化 → 代码 → 统计检验（效应量+CI+p值）
- 22:00-23:00 Day1 检查：假设 4-8 条 ✓ 符号表 ✓ 数据结构发现已写入报告（每条有下游对应）✓ Q1 完整 ✓ Q2 框架 ✓（对照 ANALYSIS_MODELING_REPORT 骨架）

## Day 2：Q3Q4 + 灵敏度
- 08:00-12:00 Q2 收尾 + Q3：模型对比表（≥3 模型）→ 代码 → 检验
- 12:00-18:00 Q4：用 Q3 结果 → 蒙特卡洛/置换检验
- 18:00-22:00 灵敏度（调 `sensitivity-analysis`，按题型自适应）：参数≤5 单因素扫描+弹性系数；5<k≤20 Morris 筛选；k>20 Morris→top5→Sobol；优化题另做约束右端扰动
- 22:00-23:00 Day2 检查：四问完成、每问有对比表+检验、验证三件套齐备（回代/小规模精确对照/独立复算）、灵敏度独立成章、步骤可复现

## Day 3：论文 + 审校 + 提交
- 08:00-12:00 初稿：摘要（最后写）→ 1.3 贡献表 → 技术路线段 → 图表 → 结论 → 参考文献
- 12:00-16:00 审校：全局格式（`math-paper-template` + official-paper-format.md）→ 建模严谨性（`statistical-diagnosis`）→ 业务解释 → 创新点
- 16:00-18:00 整理：附录文件列表+可视化+伪代码 → 编译 PDF → 逐页核对 →（可选）转 Word 交付

# 模型选型决策树（含统计检验要求）

## 先定题型

```
输出是一个数(最值/方案) → 优化类
输出是一条序列/未来值 → 预测类
输出是一个排名/打分 → 评价类
输出是一个标签/分组 → 分类/聚类类
输出是系统演化规律 → 机理/动力学类
混合题 → 主问题定主模型，子问题叠加
```

## 评价类
```
专家经验+层次 → AHP（CR<0.1 必须报）
纯客观数据 → 熵权法（报各指标信息熵；全相同指标熵权=0 属正常）
多方案排序 → AHP+TOPSIS / 熵权+TOPSIS（贴近度 C 不是百分制）
模糊语言 → 模糊综合评价（算子用 M(·,+) 而非 M(∧,∨)）
数据少信息不全 → 灰色关联；效率评价 → DEA；指标高度相关 → PCA+TOPSIS
统计要求：报权重来源+归一化方向+排名敏感性
```

## 预测类
```
数据量<15 → GM(1,1)（只适合单调近指数，震荡序列失效）
纯时序 → ARIMA/SARIMA/Prophet（ADF+KPSS 联合定阶，报滞后阶数依据）
多因素 → 线性回归/岭/Lasso（VIF>10 需处理）
非线性强 → RF/XGBoost（Nested CV+置换检验）
长序列复杂非线性 → LSTM（数据<1000 慎用）
需不确定区间 → Bootstrap/MCMC
统计要求：RMSE/MAE/MAPE + CV 均值±std；物理边界检查
高分组合：ARDL+VAR+RF → Ridge 元学习器
```

## 优化类
```
线性 → LP（Simplex；报对偶保证的最优性）
整数/0-1 → MIP（Branch&Bound；连续松弛取整必须重验可行性；报间隙）
非线性多峰 → GA/SA/PSO（固定种子、≥5 次运行、报均值±std，禁止宣称全局最优）
组合优化 → DP（报状态转移方程+复杂度）
大规模调度(万级任务) → 贪心构造+局部搜索 GLS
  + 块级MILP最优性参照（报"启发式与块级全局最优间隙"）        [华数杯 2026C 问题二实测]
超大规模联合优化(亿级变量) → LP对偶分解+交替迭代
  （报：对偶变量扰动验证、迭代收敛序列、终止准则、分段计价修正）[华数杯 2026C 问题四实测]
多目标 → 先权重端点扫描诊断前沿结构（前沿坍缩为单点须用压力场景证明"数据结构使然而非算法缺陷"，报扫描表）
        → 真实前沿用 NSGA-II / ε-约束（报各目标分量贡献）
统计要求：收敛曲线、多起点解分布、与精确解/小规模对照、复算核对表
每条"为什么不能直接求更简单的模型"必须有出处（数据发现或对比实验）
```

## 分类/聚类类
```
有标签 → RF/SVM/XGBoost（混淆矩阵+ROC/AUC+CV；不平衡数据用 F1/AUC 而非准确率）
无标签 → K-Means/DBSCAN/GMM（肘部法则/轮廓系数定 K）
图结构 → Louvain/GraphSAGE（报模块度）
```

## 机理/动力学类
```
连续时间 → ODE（SIR/Logistic/Lotka-Volterra；报初始/边界条件、守恒量、步长收敛）
空间扩散 → PDE/有限差分
不确定性 → 蒙特卡洛（≥10000 次，报 CI 不只均值）
离散演化 → 元胞自动机/马尔可夫链（报边界条件/转移矩阵每行和=1）
```

## 检验类（诊断+验证，调 `statistical-diagnosis`）
```
回归后：BP 异方差 + DW 自相关 + VIF 共线性 + JB/SW 正态性
时序后：ADF+KPSS 联合 → Johansen 协整 → Granger（报滞后阶数）
事件研究：JB → Corrado+Patell+BMP+Bootstrap(BCa CI)；事件日聚集>5% 时 Corrado 失效
ML 后：Nested CV + 置换检验 + Cohen's d
每个检验：效应量 + p值(必要时多重比较校正) + 实质性结论
```

# 提交前检查清单（★=与一等奖的核心差距）

## 结构与内容（25 项）
```
□ 摘要≤1页、含每问方法+定量结果、无表格/公式 ★
□ 关键词 3-5 个 □ 1.1 背景有引用 □ 1.2 自组织语言重述
□ 1.3 主要贡献表 ★ □ 每问分析有技术路线总结 ★ □ 问题分析无结果泄漏 ★
□ 符号三线表(符号|说明|单位) □ 假设 4-8 条且正文引用
□ 每模型有目标函数+约束 ★ □ 每求解有算法步骤 ★
```
