# 数模解题提示词资产包（prompt-pack）

> 来源：华数杯 C 题全程实战记录（codex 会话）中**被验证有效**的 14 条提示词模式。
> 用法：按比赛阶段复制对应提示词到任意 AI 会话（DSH/codex/opencode）。DSH 内更省事的入口：直接说"用 competition-workflow 走流水线模式"（≈ /math-model-agent），本包中的检查项已制度化为该 skill 的阶段与检查清单。
> 每条标注：**时机 / 原话模板 / 判定标准 / 实测效果**。

---

## A. 读题与文献阶段

### A1 外部解题指南逐条核验
- **时机**：拿到任何 AI 生成的"解题指南/参考方案"后，建模前。
- **模板**：`分析题目，了解其研究背景，进行相关文献检索。这是一份解题指南：[贴全文]。请逐条核对它是否准确：①与题目原文是否一致；②与附件数据口径是否一致（用代码实测）；③引用的文献是否存在、DOI/卷期页码是否正确。输出"✅一致 / ❌错误（需修正）"分项清单。`
- **判定**：每条断言必须有实测或出处；无出处即标"未证实"。
- **实测**：华数杯 C 题指南被查出 5 处实质性错误（Q2 成本口径、Q4 利用率口径、SOC off-by-one、成本时域、套利描述方向）。

### A2 文献事实核验
- **模板**：`用 Crossref/Semantic Scholar/OpenAlex 核实以下文献的 DOI、卷期、页码：[文献列表]。检索不到或不一致的，明确说"无法核实"，绝不编造卷期页码。`
- **判定**：每条文献可给出 DOI；无法核实的标注清楚，论文中删除或降级为"未查证"。

### A3 读题双通道
- **模板**：`pdf 用 vision-ocr 读，并与文本层提取对比，确认没有遗漏图表/公式。`

## B. 计划阶段

### B1 交付物命名规范（先定结构再动手）
- **模板**：`最终需要交付：数据预处理-数据预处理.py-其附件；问题一-problem1.py-其附件；问题二-problem2.py…；每问一个报告N.md；论文用 tex 生成 pdf。`
- **判定**：文件命名固定 → 跨会话/跨工具可交接（codex 交接摘要正是靠这个）。

### B2 阶段门 + 迭代记录（核心方法论）
- **模板**：`整体建模过程需要严谨，结果需要达到最优。一个问题一个问题解，把问题分成多个子问题；解完一个问题后，先验证其结果是否严谨且性能优、可解释性强；如果结果太差（比如拟合优度不到 80、最好要到 90 左右），或有系统性误差，就需要不断优化——一个子问题可以先优化个两三次，然后记录你优化的过程，写成报告.md，最后便于写论文。可视化字体要更大一些，特殊值需要标注。`
- **判定**：不达标必须迭代；每轮优化记录"改动→效果→指标"。

### B3 显式阶段门（更细的分段）
- **模板**：`数据预处理 → 报告1.md（做完检验直到你觉得没有问题后）→ 问题一 → 报告.md（检查模型效果和建模逻辑严谨性，是否有其他可用的解释性强的模型，是否需要对数据进行进一步分析等），通过后 → 问题二，以此类推。`
- **判定**：上一阶段报告未通过自检，不得开始下一阶段。

### B4 计划-评审-批准-实施环
- **模板**：`/plan [需求]。` → 收到计划后提修改：`再优化一下细节，这个机制如何进行灵敏度检验？是否是现在看来的最优解？如何检验，如何交付？` → 满意后：`PLEASE IMPLEMENT THIS PLAN.`

## C. 求解阶段

### C1 性能门槛
- **模板**：`怎么一直运行这么慢，能不能更加高效的方法。`
- **判定**：求解器单次运行超过时间预算（如 10 分钟）必须评估换算法（如滚动 MILP→贪心+局部搜索），并保留小块精确求解做质量对照（华数杯实测：几小时→93 秒，块级 MILP 间隙 0%）。

### C2 全链路一致性
- **模板**：`问题一的思路变了，后面问题二三四的思路是不是也应该变一下？问题二是否也可以用基础模型或组合模型，做一个解释性强的模型？以此类推，做到整个解题过程链接起来，有逻辑且适用度高。`
- **判定**：任一问方法变更后，下游各问的输入口径/模型假设必须同步复查。

### C3 赛后批判性诊断
- **模板**：`现在完成了初步建模，但是还有很多问题：[具体疑虑]。图我觉得想表达的意思不明显且数据不美观（用 vision-ocr 读图验证）；很多图显示模型在处理后是无效的，结果不好；整体的口径和数据管线是个大问题，需要解决。`
- **判定**：诊断必须落到代码级证据（哪个函数、哪个口径错了），并产出统一口径修复。

### C4 第三方诊断复算 + 文献一致性
- **模板**：`你也可以先看看这份[诊断报告]，分析一下他说的是不是对的；再根据文献内容，分析现有结果是否与文献内容相符（一般要求相关）。`
- **判定**：对第三方意见逐条复算（实测：审查报告 80% 正确但 3 处机制错误+2 处文献数字造假，全部被复算拦截）；结果与文献量级/方向对照（如"碳降 76%"远超文献上限时，必须用绝对量+机制双口径解释）。

## D. 写作阶段

### D1 国奖范式重构
- **模板**：`已创建通用 skill guozhan-paper（含 OCR 语料与范式）。请分析并修改现有论文，并在最后做出一个通用型 skills。`
- **DSH 对应**：直接触发 `guozhan-paper`（七段式+流程图两层+R1-R4+严谨性规范+检查清单）。

### D2 排版硬要求
- **模板**：`不要目录，不要页眉，只需要页码，整体紧凑，不要有太大空白，按照论文模板来。`

### D3 引用一致性
- **模板**：`检查参考文献顺序与正文引用顺序是否一致、是否有未引用的文献。` + A2 的不编造原则。
- **判定**：正文首个引用必须是参考文献[1]；每条文献有 DOI 或已核实出处。

## E. 人设（AGENTS.md 版，可选注入会话开头）
`你是我的专属"全栈架构师与统计学科研导师"。全程中文；执行前先批判性审视思路并指出风险；先讲 Why（原理）再给 How（实现），拒绝保姆式代写；统计问题按"原理→数据要求→代码→结果解读→潜在陷阱"输出；学术文书按"结构→图表→措辞→引用"输出。`
