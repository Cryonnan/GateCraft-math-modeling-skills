## 1. 流程图两层模板（C023 图2/3/7/9/10 实测）

### 第 1 层：总体技术路线图（置于"1.3 我们的工作"）
四问串成一条链，问题间箭头标注**传递物**：

```
问题一（方法链：数据→模型→求解→分析）
  └─传递物：浓度预测模型 p(t,b) ──→ 问题二（达标时点优化：分组+DP）
       └─传递物：分组推荐时点 ──→ 问题三（协变量扩展：AGE/G/P + DP）
            └─传递物：判定思路/校准样本 ──→ 问题四（Z 值+FDR+一致性聚合，独立支线）
```

### 第 2 层：每问四阶段流程图（节点内容=本问关键词，禁止空泛步骤）

| 阶段 | 问题一（统计建模） | 问题二（优化） | 问题三（扩展优化） | 问题四（统计判定） |
|---|---|---|---|---|
| ①数据 | 清洗/logit 变换/GA·BMI 中心化 | 计算达标概率 p(t,b)、最早达标时间 T*(b) | 决策变量扩展：BMI 断点/推荐孕周/协变量偏移 | 变量提取+孕周分层（Early/Mid/Late） |
| ②模型 | 与 GLM 对比 → 选 LMM | 目标：加权总风险+分组复杂度惩罚 λK | 目标升级：个体协变量+时间风险+稀疏正则 Ω(γ)=p‖γ‖₁ | 男胎回归校正+稳健参数(MAD)+Chr21 用 t 分布 |
| ③约束/检验 | 固定效应+随机效应+残差 | 保障率/可执行/覆盖非重叠/**单调性约束** | 约束强化：保障率+平滑性+一致性 | 标准化 Z+多重检验校正(BH)+FPR≤1% 阈值优化 |
| ④求解/分析 | 求解+结果分析 | **动态规划 DP**+敏感性分析 | DP 分段+多维敏感性+协变量量化 | 综合判定+**k=2 一致性聚合** |

要点：框内直接写约束名与算法名（如"保障率约束""DP""k=2 聚合"），评审扫读即可判断工作量；方案比选不进流程图（用比选表，见 guozhan-paper 3.2）。

## 2. 图型模板（每张图服务一个决策点）

### 2.1 诊断图：热力图（C023 图4，p6）
- 服务决策：变量间关系是否非线性 → 决定模型是否引入二次项/交互项。
- 做法：两变量离散化为区间网格，计算格内均值填色；正文紧接一句"诊断结论→模型形式"因果声明（"非单调→排除线性→引入二次项"）。

### 2.2 诊断图：小提琴图组（C023 附录B，p25）
- 服务决策：确认变换与结构假设（logit 变换、随机效应、单调约束）。
- 做法：因变量按分组（BMI 分位/孕周分位/质量变量）画小提琴，观察中位数移动与尾形；观察结论编号写进正文。

### 2.3 关系图：预测曲线+置信带+决策阈值虚线（C023 图5/6，p9）
- 服务决策：模型结论的临床/业务含义（FF~GA 单调上升、~BMI 倒 U）。
- 做法：群体平均预测曲线+95% CI 阴影带，叠加业务阈值虚线（如 4% 临床阈值）并标注；caption 直接写结论。

### 2.4 决策结果图：连续解与台阶化叠加（C023 图8，p13）
- 服务决策：连续最优解 vs 可执行分组策略的差距 → 论证"台阶化代价可接受"。
- 做法：连续建议曲线 + K 段阶梯线同图叠加，断点标数值；旁配取整摘要表；精确值另用正式表（表4）。

### 2.5 结果图：阈值线+三色散点（C023 图13，p22）
- 服务决策：阈值区分度与稳健性（Chr13/18 分离良好、Chr21 经 t 校正后厚尾受抑）。
- 做法：三子图并排（各染色体），散点按结论三色，阈值线虚线标注数值（z=2.6）。

## 4. 流程图生成链路与委派模板（无视觉模型的闭环）

**决策**：流程图以**机器可读规格（spec JSON）为单一真源**——drawio 代码与 PNG 由 `../../assets/flowchart_gen.py` 确定性生成；需要委派给有视觉的模型重绘时，把同一规格转成提示词。禁止先写提示词后写规格（prompt→spec 有损，spec→prompt 无损）。

### 4.1 规格格式（阶段 1 的「流程图草稿」字段按此写）

```json
{ "kind": "stages", "title": "问题二：…", "stageTitles": ["①数据处理","②模型建立","③约束与检验","④求解与敏感性"],
  "stages": [["计算达标概率 p(t,b)","最早达标时间 T*(b)"], ["目标：加权总风险","分组复杂度惩罚 λK"],
             ["保障率约束 q=0.95","可执行域/覆盖非重叠","单调性约束"], ["动态规划 DP","κ×q 敏感性分析"]],
  "edgeLabels": [null,null,null], "out": "outputs/p2_flowchart.drawio" }
```
总体路线图用 `"kind":"chain"`：`"chain":[{"title":"问题一","methods":[…],"pass":"浓度模型 p(t,b)"}, …]`（pass=传递物，画在箭头上）。

### 4.2 生成与三产物

```text
python ../../assets/flowchart_gen.py spec.json
→ spec.drawio   # drawio 桌面版/网页版可直接打开美化
→ spec.mmd      # mermaid 预览（渲染环境通用）
→ spec.png      # matplotlib 渲染（中文安全；供 OCR 复核/直接插图）
```

### 4.3 OCR 读回复核（无视觉验收，阶段 5 必做）

1. vision-ocr 8B 读回 PNG 全部文字；
2. 把 spec 的全部项（标题+节点+传递物）与读回文字逐项比对（**归一化**：κ↔k、λ↔λ、希腊字母↔拉丁替代视为命中）；
3. 未命中项 = 渲染缺失/截断，修正 spec 后重新生成。
- 本链路实测（C023 问题二四阶段 + 总体路线图）：15/16 项与 16/16 项读回命中，唯一"未命中"为 κ→k 字形替代。

### 4.4 委派重绘提示词模板（交给有视觉的模型时）

```text
以下是流程图规格（JSON）。请用 [drawio / 专业流程图风格] 重绘，要求：
1) 保持四阶段顺序与全部节点文字一字不差；2) 箭头标签为传递物；3) 配色统一、字号≥可读阈值；
4) 输出 .drawio 源码。完成后再自查：逐项确认规格中的每个文字都出现在图中。
[粘贴 spec JSON]
```
判定：委派产出的任何渲染结果同样过 4.3 的 OCR 读回核对。

## 3. 图表对账脚本思路 v2（阶段 5 执行）

```text
1. 引用集合 C：grep -oE '(图|表)[[:space:]]*[0-9]+(-[0-9]+)?' 正文（排除 caption 行）
2. caption 集合 T：grep -E '\\caption\{'（figure/table 环境内）
3. 检查项：
   a. C ⊆ T（引用了不存在的编号 → 列出）
   b. T 无缺号/重号（表8-2 出现两次 → 列出）
   c. 前缀统一（出现"图表N"混用 → 列出）
   d. 章节号残留（grep '\b[0-9]+\.[0-9]+\.[0-9]+\b' 非公式行，如"3.1.2""2.3.4" → 列出）
4. 另做：摘要数字映射（摘要段数字集合逐一映射正文表格）、AI 工具名 grep（GPT|DeepSeek|Claude|Qwen|Kimi）。
```
实证：2023C/2026 华数杯/泰迪杯/大湾区杯四篇实测中，仅靠人工核对全部漏过至少 1 处编号错误——必须脚本化（C023 自身也有图12/13 引用错位）。
